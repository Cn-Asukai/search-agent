# 汉化检索评测基准

用来衡量检索改动有没有用。不改线上检索行为。

目标规模 **100～200 部、按难度分层**。这是后续填充目标，不是本文件已经收齐的数量。开放网络很难建立「绝对没有」的真值，负例必须写明检查范围和日期。

## 样本格式

`docs/eval/samples.json` 是数组。每条：

| 字段 | 含义 |
|---|---|
| `id` | 稳定样本 id |
| `query` | 提交给服务的查询词 |
| `type` | `novel` / `manga` / `unknown` |
| `difficulty` | `easy` / `medium` / `hard` |
| `identity` | 期望认到的原名、媒介；同名消歧要点 |
| `official` | `confirmed` / `not_found` / `unknown` |
| `fan` | 同上 |
| `notes` | 人工备注 |
| `checked_at` | 人工核对日期 `YYYY-MM-DD` |
| `checked_scope` | 负例或 unknown 时：查过哪些方向 |

`unknown` 表示人工也未核实，不算漏检，也不算误报。

禁止在样本里虚构汉化组名称或链接。

## 分层

样本应覆盖（可交叉）：

- 热门 / 冷门
- 只有官方、只有民间、两者都有
- 多译名、同名作品
- 小说有中文但漫画没有已知证据
- 只有英文翻译
- 只有试译、机翻或授权公告
- 聚合站转载官方内容
- 原发布页失效
- 存在事实明确但进度未知

## 指标

| 维度 | 怎么算 |
|---|---|
| 身份准确度 | 是否认对作品与媒介 |
| 存在判定精确率 | 系统判为有中文的结果中，多少有合格证据 |
| 已知正例召回率 | 样本里 `confirmed` 的版本，找到了多少 |
| 来源分类准确度 | 官方转载是否被误判为民间汉化 |
| 引用支持率 | 引用页面是否真正支持对应结论 |
| 覆盖完整度 | 官方、民间是否分别完成必要检查 |
| 可用性 | 得到可行动答案的比例，而不是全部退回未知 |
| 效率 | P50 / P95 延迟、外部调用数、token 与费用 |
| 稳定性 | 同一作品重复查询是否出现无依据的结论变化 |

不要只提高精确率：把所有难题都答「未知」也能减少误报，却没有产品价值。

改动时做对照，分别看：别名、搜索渠道、证据规则、缓存、停止策略。看新增有效证据和成本，不看输出是不是更长。
